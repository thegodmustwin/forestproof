## Runtime

Use the versioned code under `/opt/forestproof-visibility/current`, an isolated pinned raster environment under `/opt/forestproof-visibility/venv`, and the dedicated unprivileged `forestproof-visibility` account. The units in this folder share `/var/lib/forestproof-visibility` for the atomic report state. The web unit has read-only access and binds to host loopback port 18450. Its HTTP interface is separate from the case API and demo storage.

The timer checks twice per day at 03:15 and 15:15 EAT, plus an initial activation check. It scans a 30-day catalog window and inspects up to three acquisition days. A selected day must contain both expected grids for the same datatake. Unchanged asset identities reuse previous measurements. A changed object is measured in a size-limited read. A full refresh reads up to 48 MiB plus the bounded catalog response and exits on the first failed source read. The unit has a three-minute runtime limit. A failure retains the last valid report. The web process calculates overdue status at request time so a stopped timer cannot freeze the fresh status.

## Operate the site

Visitors enter through HTTPS on the Contabo hostname. Caddy sends the 32 exact public paths to the Python listener on `127.0.0.1:18450`. Its separate authenticated route serves the private preview. The public process reads validated JSON from `/var/lib/forestproof-visibility/source.json` and generates HTML. The refresh timer runs independently. The successful source-check date and satellite acquisition dates describe different events. The planetary homepage leads to a geographically placed research rectangle and exact historical source-image footprints. The atlas preserves date/grid selection when opening the observation laboratory. Without JavaScript, the full dated archive remains open. The homepage also compares two real dated source visualization crops; its Earth image is explicitly a historical NASA composite.

The visibility server whitelists each public asset and sends content hashes as ETags. Browsers revalidate assets across releases. The atlas alone permits same-origin workers and connections plus data/blob images for the local map renderer. Other public routes retain their stricter policy. The atlas loads terrain tiles only when a visitor requests 3D; elevation is historical context at 1× scale, not a vegetation measurement. Failed browser graphics preserve a real 2D relief map, pan/zoom/reset and the evidence archive. The vendored runtime needs no API key or paid map service. Source identity, licences, hashes and derivation are documented in `assets/geography-provenance.json`, `assets/atlas-runtime.json` and the asset README. No provider credential or private receipt is delivered to the browser.

systemctl status forestproof-visibility.service --no-pager
systemctl list-timers forestproof-visibility-refresh.timer --all
journalctl -u forestproof-visibility-refresh.service -n 12 --no-pager

## Gateway and verification

Confirm the exact installed gateway, loopback listener, original auth and bind mount. First verify the live worker and check that the state and case paths return 404 at the loopback listener. Insert [the public matcher](public-route.caddy) ahead of the existing authentication in the explicit Caddy `route` block, preserving all fallback directives. Validate the candidate in the installed Caddy container and retain a root-private copy of the previous config. Use the existing gateway's supported reload procedure. The installed gateway disables the admin API. A supported signal reload requires a file-based start without `--resume` or prior API configuration. [Caddy command and signal documentation](https://caddyserver.com/docs/command-line#signals)

Verify all 32 public paths over certificate-validated TLS, with GET and HEAD returning 200, expected MIME types and POST returning 405. Empty `maplibre-gl-shared.mjs` is a legitimate vendor module. Verify anonymous requests to the existing preview, API, private report and unlisted asset/atlas paths still require authentication. Confirm SSH and xrdp are active, RDP remains loopback-only, and the timer has actually executed. Verify the failure and expiry states with isolated test data. If a release check fails, restore the saved gateway configuration and previous release link through the same procedure. Leave existing application containers and database intact.
