# UI art direction

Make the product recognizable through decisions that serve its audience. This is an original workflow; read [references/design-library.md](references/design-library.md) when choosing references.

Before editing, inspect the relevant product context, existing UI and real content. Find the primary user job, the most important action, the emotional register and the facts the page can support. If they are clear, proceed without a questionnaire. Retain established conventions unless the request calls for changing them.

Choose a concrete direction: explain in a sentence what makes this product's interface distinctive and useful. Select composition, type pairing, surface/color roles, spacing, density and imagery to support it. Use the existing stack and tokens where practical. A reference is evidence of a useful decision, not a template to clone.

## Decisions that change the result

- Give the page a dominant reading order and a visible next action. Avoid equal-weight sections when the user's priorities differ.
- Use expressive type where it helps identity and legible type for work. Build hierarchy through scale, line length, weight, space and alignment before adding decoration. Long titles and narrow screens must work.
- Let content select the layout: a ledger, map, editorial spread or workbench may serve better than repeating cards. Use cards when they represent meaningful groups.
- Choose color by role: brand, emphasis, interaction, warning and uncertainty are distinct. Preserve semantic consistency and do not rely on color alone.
- Use real, licensed assets or original code-native graphics. Do not invent metrics, testimonials, source health, customers or proof of impact to fill space.
- Motion should explain a state change or orient attention. Avoid blocking work, perpetual ambient motion and motion that ignores reduced-motion preferences.
- For tools and dashboards, visual confidence comes from precision and helpful density as much as spectacle. Do not turn a work surface into a marketing page.
- Keep useful familiar interaction conventions. No universal bans on fonts, gradients, cards, dark mode or palettes: choose and justify them in context.

For a small fix, preserve the current visual direction and change only the affected component. For a redesign, implement a coherent screen rather than a list of cosmetic tweaks. Finish by rendering and inspecting the primary view and a narrow view using available browser tools. If this is impossible, report that limitation and provide the best reviewable code/artifact; a passing build is not visual verification.

Respect current authorization for publication, paid assets and external actions. This skill supplies design judgment, not new permissions.
