## Workflow and recovery: separate evidence gates

1. Authenticate the actual owner and enforce server-side authorization before handling genuine cases; the public fictional walkthrough and shared synthetic demo do not satisfy this.
2. Use separate live storage, explicit source/record/version identity and provenance, freshness and failure states. Replay a permitted source record without creating duplicates. Never replace unavailable live data with demo fixtures.
3. Record the owner's own review, response and follow-up. A prior screenshot shows FP-RESEARCH-001 saved as open for verification; it is a genuine **historical research** observation, not a current qualified alert. Its original receipt and private notes must stay private.
4. Use a protected copy stored outside the source system, restore on an independently accessible environment, and compare the exact original receipt, owner decision, follow-up and dossier. Test recovery after loss of the original machine/profile using an owner-controlled recovery mechanism. A same-host copy or a synthetic rehearsal does not prove this.
5. Publish only explicitly approved fields with source attribution and clear stale/unavailable status. Keep private case/API routes protected.
